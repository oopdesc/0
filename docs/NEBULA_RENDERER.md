# トップの星雲をつくる

空間の濃淡をつくり、光を重ね、星を描く。トップの「光と塵のあいだ」は、その三つを組み合わせた作品です。写真を動かしているのではなく、ブラウザ内で視点ごとに描いています。

天体の観測や、物理的に検証された星形成のシミュレーションとは異なります。色と形は作品として選んでいます。

## コードをたどる順番

1. [HomeNebula.tsx](../web/src/art/HomeNebula.tsx) が画面とボタンを受け持ちます。描画コードは必要になったときに読み込みます。
2. [field.ts](../web/src/art/nursery/field.ts) が再現できる乱数の立体テクスチャと、カメラの位置・向きをつくります。同じ種なら同じ雲の材料になります。
3. [shaders.ts](../web/src/art/nursery/shaders.ts) の `volumeFragment` が、視線上の雲を奥行き方向にサンプリングします。細かな濃淡をいくつかの大きさで重ね、暗い塵と光る縁を描きます。
4. [renderer.ts](../web/src/art/nursery/renderer.ts) が、雲を描く小さな画面、合成する画面、星の層を順に描画します。操作はカメラの位置と向きを変えます。

## 光を少しずつ重ねる

雲の一部分の濃さを `d`、視線を進む幅を `Δs` とすると、作品では `a = 1 − exp(−d Δs)` を、その部分から加える光の重みとして使います。

手前を通り抜けてきた光の割合を `T` として、色へ `T × a × 光の色` を加えます。その後の `T` を小さくすれば、奥の光が手前の塵に隠れます。この順番が奥行きの手がかりになります。

これは吸収を表す指数関数を使った描画上の近似です。散乱、実際のガス組成、星の形成時間を計算しているわけではありません。

## 小さく変えて、確かめる

最初は一つだけ変え、結果を比べてください。カメラの初期位置や雲の色なら、処理の上限を増やす必要はありません。

- `cold` の青と緑の成分を少し変えます。どの雲の色が変わり、どこは変わらないでしょうか。
- `cameraBasis` の引数を変えます。画像自体をずらすことと、立体の視点を変えることは、星と雲の位置関係にどんな違いを生むでしょうか。
- 光の吸収を弱めます。奥が見える代わりに、暗い塵の輪郭が失われるか確かめます。
- `noiseVolume` の種を変えます。描画の仕組みを変えずに、雲の形だけを変えられるか確かめます。

## 動作を軽く保つ

通常の上限は14fps、小さい画面では10fpsです。雲の描画は最大42万画素、小さい画面では13万画素に抑え、最後に星を別の層として合成します。画面外、別タブ、停止中は連続描画を止めます。「動きを減らす」設定では、操作時に必要な画面だけを描きます。

GPU時間を計測できる環境では、重い場合に品質を下げ、さらに重い場合は静止画へ切り替えます。上限を増やして速さの限界を探す処理は行いません。端末により速度は変わるため、一定のGPU使用率を保証する仕組みではありません。

WebGL2が利用できないときは、この作品の実描画から保存した静止画を表示します。

## 手元で確認する

このリポジトリの通常の起動・Eclipse取り込み方法は [README](../README.md) を参照してください。

```sh
npm --prefix web run dev
npm --prefix web test
npm --prefix web run build
```

Java・Rustの教材や採点とは別の描画部分です。ここを変更しても、固定のテスト結果を新しいコードの合格判定に使わないという採点の原則は変わりません。
